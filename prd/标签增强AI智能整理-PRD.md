## 1. 背景与问题

### 1.1 现状

产品目前有两条整理路径：

| 路径                         | 机制                                                          | 现状问题                                                 |
| ---------------------------- | ------------------------------------------------------------- | -------------------------------------------------------- |
| 标签整理（`use-move`）       | 视频标题 `includes(keyword)` 子串匹配后直接移动               | 命中率低：标题必须逐字包含关键词；黑盒执行无确认环节     |
| AI 智能分类（`use-ai-move`） | AI 读取标题 + 收藏夹列表（含标签）输出归类方案，review 后执行 | 全部视频都走 AI：配额消耗大、速度慢；AI 结果无置信度区分 |

同时收到用户反馈"用不明白"：标签路径概念成本高（默认收藏夹 + 标签 + 匹配规则），且关键词生成不稳定（AI 流式提取存在丢词问题，本地 TF-IDF 为 n-gram 暴力切分）。

### 1.2 核心判断

1. **标签不应承担"命中所有视频"的责任**，子串匹配注定覆盖率低；
2. **AI 不应处理所有视频**，字面可确定的归类没必要消耗配额和时间；
3. 两者互补：标签提供**确定性、瞬时、免费**的高置信归类；AI 提供**语义兜底**；
4. 用户确认过的归类结果可以**反哺标签**，形成"越用越准"的正循环，同时解决关键词生成不稳定的问题（关键词来自真实归类而非凭空生成）。

### 1.3 方案概述

用户视角只有一个主入口「智能整理」，内部为两段式流程：

```
默认收藏夹视频列表
  ├─ 第一段：标签预匹配（瞬时、免费、确定性）
  │    ├─ 唯一命中某收藏夹标签 → 高置信归类建议（source: tag）
  │    └─ 多个命中 / 无命中 → 交给第二段
  └─ 第二段：AI 语义裁决（仅处理第一段未决视频）
       └─ Prompt 携带各收藏夹标签作为"已确认的内容特征"先验
  → 统一进入 Review 面板（按置信度展示）→ 确认执行
  → 执行成功后：确认结果反哺标签（建议补充，用户采纳）
```

## 2. 目标与成功指标

### 2.1 产品目标

1. 单一入口即可完成整理，用户无需理解标签机制（解决"用不明白"）；
2. 显著降低单次整理的 AI 调用量与耗时；
3. 标签体系通过反馈闭环持续积累，命中率随使用提升；
4. 归类结果可解释（展示命中标签或 AI 理由），提升用户确认效率与信任。

### 2.2 成功指标

| 指标                                        | 基线                       | 目标                 |
| ------------------------------------------- | -------------------------- | -------------------- |
| 单次整理中标签直接命中（免 AI）的视频占比   | 0%（现状标签路径命中率低） | ≥ 30%（使用 4 周后） |
| 单次整理 AI token 消耗 / 耗时               | 现状全量走 AI              | 下降 ≥ 40%           |
| Review 面板确认率（用户未修改直接确认比例） | 未统计                     | ≥ 70%                |
| 标签建议采纳率                              | —                          | ≥ 50%                |

> 度量依赖本地埋点（见第 6 节），不上传任何数据。

## 3. 功能需求

> 优先级：P0 本期必做；P1 尽量做；P2 可顺延。
>
> ⚠️ 按 AGENTS.md 规范：涉及 UI 的功能（F2/F3/F4 的界面部分）实现前必须先通过 `ui-ux-pro-max` 产出设计方案并经确认。

### 3.1 【P0】F1：两段式混合整理引擎

#### 3.1.1 第一段：标签预匹配

对默认收藏夹的每个视频，用其标题与**除源收藏夹外**所有收藏夹的标签做匹配：

| 规则             | 说明                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 归一化           | 标题与标签统一 `toLowerCase()`、去除首尾空白后匹配                                             |
| 匹配方式         | 标题子串包含标签（与现有 `use-move` 一致，保持行为可预期）                                     |
| 唯一命中         | 命中的标签全部指向**同一个**收藏夹 → 判定为高置信结果，`source: 'tag'`，记录 `matchedTags`     |
| 多重命中         | 命中多个**不同**收藏夹的标签 → 进入第二段 AI 裁决（命中的收藏夹作为 AI 的候选提示传入 prompt） |
| 无命中           | 进入第二段 AI 裁决                                                                             |
| 命中源收藏夹自身 | 视为"保留原地"，`status: 'skipped'`，不进入 AI                                                 |

- 预匹配为纯本地同步计算，无网络开销；
- 视频数量很大时（>2000）预匹配也应在 100ms 内完成（标签总量有限，复杂度 O(视频数 × 标签数)）。

#### 3.1.2 第二段：AI 裁决

- 仅将第一段未决视频（多重命中 + 无命中）送入现有 AI 流程（`fetchAIMove` → background 流式）；
- **候选集收窄**：多重命中的视频，在 prompt 中附加"该视频标题命中了以下收藏夹的标签：A、B，请优先在这些收藏夹中选择"；
- **先验强化**：`buildAIMoveMessages` 的 prompt 措辞强化："标签代表该收藏夹中已被用户确认的内容特征，归类时优先参考"；
- AI 结果 `source: 'ai'`，沿用现有流式解析与 `resolveAIResult` 标题对齐逻辑；
- 没有任何标签的用户：行为与现状完全一致（全量走 AI），保证向后兼容。

#### 3.1.3 数据结构变更

`AIMoveResult`（`src/popup/components/ai-move/types.ts`）新增字段：

```ts
type AIMoveResult = {
  // ...现有字段保持不变
  /** 结果来源：标签命中 / AI 裁决 */
  source: 'tag' | 'ai'
  /** 标签命中时命中的标签列表（用于展示依据） */
  matchedTags?: string[]
}
```

#### 3.1.4 执行模式兼容

- `aiMoveExecutionMode: 'ask'`（默认）：两段结果合并后进 Review 面板；
- `aiMoveExecutionMode: 'auto'`：两段结果合并后直接执行（与现有 auto 语义一致），完成 toast 中区分标签命中数与 AI 数。

### 3.2 【P0】F2：Review 面板置信度展示

**目标**：让用户快速分辨"可信结果"与"需人工判断的结果"，提高一键确认率。

#### 3.2.1 展示规则

1. **排序**：标签命中结果置顶，AI 结果在后；两组内保持原顺序；
2. **依据展示**：
   - `source: 'tag'`：显示标签徽标"命中标签「xxx」"（多个标签最多显示 2 个 + "+N"）；
   - `source: 'ai'`：显示 AI 的 `reason`（现状保持）;
   - `isFallback`（AI 未匹配到收藏夹）：红色警示样式，提示"AI 未能识别目标，请手动选择"；
3. **分组标题**：两组上方显示分组说明，如"标签命中 · 12 个（建议直接确认）"与"AI 建议 · 8 个（请核对）"；
4. **批量操作**：提供"全选标签命中项"快捷操作；
5. **修改目标**：用户手动改目标后，该项 `source` 标记为用户已调整，不再参与反馈闭环的标签建议（见 F4）。

#### 3.2.2 交互约束

- Review 面板现有能力（单条修改目标、取消、确认）全部保留；
- 新增展示元素不得破坏 384px 宽 Popup 下的可用性；
- 分析中阶段的进度文案更新为两段式："标签已匹配 X 个，AI 分析中 Y/Z 个"。

### 3.3 【P0】F3：入口整合与简化

**目标**：用户只需要认识一个按钮。

#### 3.3.1 需求明细

1. **主按钮**：现有「AI 移动」按钮升级为视觉主按钮，文案改为「智能整理」，副文案/tooltip："自动把默认收藏夹的视频归类到合适的收藏夹"；
2. **标签整理降级**：「通过标签整理」从主操作区移除，入口迁移至设置页或更多菜单，标注"规则整理（高级）"；原 `use-move` 逻辑保留不删除；
3. **前置检查**（点击智能整理时）：
   - 未设默认收藏夹 → 引导 Dialog："智能整理会处理默认收藏夹中的视频" + 「去设置」按钮（高亮收藏夹区域的设置交互）；
   - 无任何标签 → 不阻断，但在开始前的确认信息中提示"还没有标签，本次将全部由 AI 分析；整理完成后可沉淀标签，下次更快"；
   - 免费模式且配额不足 → 阻断并提示，附「配置自己的 AI」出口；
4. **默认收藏夹设置显性化**：收藏夹卡片 hover 显示"设为默认"星标按钮，已默认的显示角标（长按交互保留）——继承自原引导 PRD 的 F2，因为它是主路径的前置条件。

### 3.4 【P1】F4：反馈闭环——确认结果反哺标签

**目标**：标签从"一次性生成"变为"从用户确认的归类中沉淀"，解决关键词不稳定与命中率低两个问题。

#### 3.4.1 触发时机

执行完成且 `successCount ≥ 1` 时，按**实际移动到的目标收藏夹**（用户在 Review 中修改过的以修改后为准）聚合本批视频标题。

#### 3.4.2 候选关键词生成

- 优先使用**本地提取**（复用 `keyword-extractor` 的 TF-IDF，对这批标题做提取），零配额消耗；
- 每个目标收藏夹生成 3-5 个候选词，过滤规则：
  - 已存在于该收藏夹标签中的 → 去重；
  - 长度 < 2 的纯英文/数字、停用词 → 过滤；
  - 出现频次需在批内 ≥ 2 或该批视频数 < 4 时放宽为 ≥ 1；
- 仅当某目标收藏夹本批新移入视频 ≥ 3 个时才生成建议（样本太少没有统计意义）。

#### 3.4.3 展示与采纳

1. 完成页（`stage: 'finished'`）追加"标签建议"卡片：按收藏夹列出候选词（chip 形式）；
2. 每个收藏夹一组操作：「采纳全部」/ 单个 chip 点击切换采纳与否 / 「跳过」；
3. 采纳后写入 `keyword` store（沿用现有结构与 IndexedDB 持久化）；
4. 每个收藏夹标签总数上限 20，超出时提示"已达上限，可前往标签管理器清理"；
5. 建议卡片可整体关闭，关闭不影响整理结果；本次生成的建议不重复弹（按 run 内存态，不持久化）。

#### 3.4.4 边界情况

- 用户关闭完成页未做选择 → 不写入任何标签，不追问；
- 本次整理全部为标签命中（无新增归类模式）→ 仍可为命中标签增加"命中计数"埋点，但不弹建议；
- auto 执行模式下同样在完成页展示建议卡片。

---

### 3.5 【P1】F5：配额与性能保护

1. **开始前预估**：预匹配完成后已知"需 AI 处理的视频数"，免费模式下若预估请求批次 × 消耗超出剩余配额（`checkAIGateQuota`），在开始前提示"预计本次需 AI 处理 N 个视频，当前配额可能不足"，用户可选择继续或先去配置；
2. **短路优化**：若第一段全部命中（无未决视频），跳过 AI 阶段直接进入 Review，文案明确"本次全部由标签匹配完成，未消耗 AI 配额"；
3. 现有 `batchProcess`（1000/批）与流式解析逻辑不动。

### 3.6 【P2】F6：标签命中统计（标签管理器内）

- 标签管理页展示每个标签的累计命中次数（本地计数），帮助用户识别无效标签；
- 命中数为 0 且创建超过 30 天的标签标记"低效"，可一键删除。

## 4. 非功能需求

1. **兼容性**：无标签用户的体验与现状完全一致；`use-move` 原路径保留可用；
2. **性能**：标签预匹配 2000 视频内 < 100ms；不引入新的网络请求；
3. **无障碍**：新增徽标、分组标题、建议卡片均需 `aria` 标注；chip 可键盘操作；
4. **代码规范**：遵循 AGENTS.md（`useMemoizedFn`、禁 `void` 忽略返回值、新组件先过 `ui-ux-pro-max`）；
5. **多端**：Popup 与 SidePanel 复用同一组件树，Review 面板与建议卡片在两种尺寸下可用。

## 7. 验收标准

### F1 混合引擎

- [ ] 唯一命中标签的视频不进入 AI 请求，直接产出 `source: 'tag'` 结果且 `matchedTags` 正确；
- [ ] 多重命中与无命中的视频进入 AI，多重命中项的 prompt 包含候选收藏夹提示；
- [ ] 命中源收藏夹自身的视频标记为 skipped；
- [ ] 无任何标签时流程与改造前一致；
- [ ] auto 执行模式下两段结果合并执行，toast 区分来源计数；
- [ ] `tag-matcher` 纯函数具备单元测试（唯一命中/多重命中/无命中/大小写归一/命中自身五类用例）。

### F2 Review 面板

- [ ] 结果按"标签命中 → AI 建议"分组排序，依据（标签徽标 / reason）正确展示；
- [ ] fallback 项有醒目警示且可手动选择目标；
- [ ] 手动修改目标后该项不再产生标签建议。

### F3 入口整合

- [ ] 主按钮为「智能整理」，原「通过标签整理」迁移至高级入口且功能正常；
- [ ] 未设默认收藏夹点击时出现引导 Dialog 且可跳转设置；
- [ ] 免费模式配额不足时阻断并给出配置出口；
- [ ] 收藏夹卡片 hover 出现星标按钮，设置默认后显示角标，长按仍可用。

### F4 反馈闭环

- [ ] 目标收藏夹新移入 ≥ 3 个视频时出现标签建议卡片；
- [ ] 建议词已去重、过滤停用词，数量 3-5 个；
- [ ] 采纳后标签写入并在下次整理的预匹配中生效；
- [ ] 标签数达到 20 上限时给出提示且不写入。

### F5 配额保护

- [ ] 全部命中时跳过 AI 且文案明确未消耗配额；
- [ ] 免费模式预估配额不足时开始前给出提示。
